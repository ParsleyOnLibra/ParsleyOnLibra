# AI 보조 테스트 설계·결과 검토 기록

2026-11-23, Codex를 사용한 개인 QA 연습 기록이다. 작성 시점의 사용자 확인: 기존 회사 업무에서 AI를 활용한 사례는 없다. 이 문서의 AI 활용을 회사 실무 성과로 표현하지 않는다.

## 입력과 작업 방식

- 입력: [가상 명세](SPEC.md)의 R-01~R-05. 실제 버즈빌 SDK 또는 내부 문서는 제공하지 않았다.
- AI 요청 요지: “광고 로드·노출·완료·보상 흐름의 정상, 거부, 중복 콜백, 오프라인 복구 테스트 후보를 제안하고 요구사항 ID와 예상 결과를 붙여라. 명세에 없는 정책은 따로 표시하라.”
- Codex가 후보를 제안하고 명세와 대조해 실행 가능한 시나리오로 옮겼다. 현재 **사용자의 직접 검토 전**이다. 사용자가 코드와 결과를 확인한 뒤에만 본인의 수행 사례로 지원서에 적는다.

`채택`은 가상 명세와 일치해 테스트로 구현했다는 뜻이다. 실제 광고 SDK에서의 타당성 검증을 뜻하지 않는다.

## 실행 결과를 이용한 AI 요약과 사실 대조

AI의 1차 요약: “기본 구현에서 12개 시나리오가 통과했고, 중복 보상 결함을 넣으면 TC-08이 실패한다. 같은 거래 ID의 두 번째 완료 콜백에서 보상 기록이 한 건 더 생긴다.”

대조 근거: [`latest.json`](../results/latest.json)의 `passed=12`, `steps=59`; [`mutation.json`](../results/mutation.json)의 `failed=1`, `TC-08`의 `final credit_events`는 기대 `['tx-8']`, 실제 `['tx-8', 'tx-8']`. 원인은 의도적으로 만든 `DuplicateCreditFlow`의 중복 기록이다. 다른 케이스의 통과는 해당 결함이 모든 경로에 영향을 주지 않는다는 뜻일 뿐, 실제 제품의 안정성을 의미하지 않는다.

## 생산성 개선을 말할 때의 범위

- AI가 명세에서 후보를 넓히고, 명세 밖 정책 두 개를 검토 목록으로 분리했다.
- 채택한 12개 케이스의 59단계를 한 명령으로 반복 실행하고 JSON 증거를 생성한다. 로그를 다시 읽을 때 AI 요약을 출발점으로 쓰되 원본 결과와 대조한다.
- 사람의 작성 시간이나 작업 시간 절감률은 측정하지 않았다. 지원서에 “몇 % 단축” 같은 수치를 적지 않는다.
- 사용자는 제출 전 R-01~R-05와 TC-01~TC-12, 두 실행 보고서를 읽고 스스로 설명할 수 있어야 한다.
