# 가상 리워드 광고 QA 명세 v1

이 문서는 개인 QA 연습용 가상 광고 흐름이다. 버즈빌의 SDK, 서버, API 또는 실제 보상 정책을 설명하지 않는다. 테스트 대상은 `src/reward_sim.py`의 결정적 상태 시뮬레이터다.

| ID | 요구사항 | 확인할 위험 |
| --- | --- | --- |
| R-01 | `initialize` 후 동의 상태가 `GRANTED`일 때만 `load`가 성공한다. 동의 철회는 로드된 광고를 무효화한다. | 동의 거부·철회 후 노출 |
| R-02 | 네트워크가 연결된 상태에서만 `load`가 성공한다. `show`는 `LOADED` 상태에서 한 번만 성공하고 노출 이벤트를 한 건 남긴다. | 잘못된 순서·중복 노출 |
| R-03 | `SHOWING`에서만 `complete(txn)`을 처리한다. 온라인이면 거래 ID당 보상을 한 번만 기록한다. 같은 거래 ID의 중복 콜백은 무시한다. | 보상 중복·순서 오류 |
| R-04 | 오프라인에서 받은 완료 콜백은 거래 ID를 대기열에 보관한다. 연결 복구 시 보상을 한 번 기록하며 재연결해도 중복 기록하지 않는다. | 보상 누락·재시도 중복 |
| R-05 | 완료 전에 광고를 닫으면 보상을 기록하지 않는다. 완료 후 오프라인 대기 중 닫더라도 복구 시 보상을 기록한다. | 조기 종료·복구 누락 |

## 관측 방법과 범위

- 각 명령은 `accepted`, `code`, `state`를 반환한다. `snapshot()`에서 노출 수, 보상 거래 ID, 대기 거래 ID를 확인한다.
- 이벤트 로그에는 순번, 명령, 코드, 이전·이후 상태, 거래 ID가 남는다. 같은 명령 순서는 같은 결과를 낸다.
- 앱 UI, Android/iOS SDK, 실제 광고 네트워크, 개인정보 처리, 서버 간 보상 검증, 크래시와 ANR은 모델링하지 않는다.
- 거래 ID는 비어 있지 않은 문자열이다. 이 가상 명세에서 거래 ID의 유일성은 입력 측이 보장한다고 가정한다.
