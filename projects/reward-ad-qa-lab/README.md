# AI 보조 리워드 광고 QA 실습

버즈빌 QA Manager 지원 준비를 위해 만든 **개인 가상 프로젝트**다. 버즈빌의 SDK, 내부 코드, 운영 데이터 또는 실제 광고를 테스트한 결과가 아니다.

## 목표와 근거

1. [가상 명세](docs/SPEC.md)의 광고 로드, 노출, 보상, 중복 콜백, 네트워크 복구 요구사항을 정의했다.
2. Codex로 정상·예외 테스트 후보를 제안받고 [후보별 채택·보류 근거](docs/AI_REVIEW.md)를 남겼다. 사용자 직접 검토 전의 작업임을 기록했다.
3. [시뮬레이터](src/reward_sim.py)와 [테스트 실행기](scripts/run_cases.py)로 채택한 케이스를 반복 실행했다.
4. 중복 보상 결함을 의도적으로 주입해 케이스가 이를 검출하는지 확인했다.

## 재현

Python 3.10 이상만 필요하다. 외부 패키지나 API 키는 필요하지 않다. 저장소 루트에서 실행한다.

```powershell
python projects/reward-ad-qa-lab/scripts/run_cases.py
python projects/reward-ad-qa-lab/scripts/run_cases.py --mutation
```

2026-11-23 로컬 실행: 기본 구현 **12/12 케이스, 59단계 통과**. 의도적 중복 보상 결함 주입 시 **TC-08 실패**. 전체 명령·기대 코드·실제 코드·이벤트 순서는 [기본 실행 JSON](results/latest.json)과 [결함 주입 JSON](results/mutation.json)에 있다. 실행 시간은 기기 상태에 따라 바뀌므로 생산성 향상 수치로 사용하지 않는다.

## 설명할 수 있어야 할 것

- AI의 후보가 명세에 근거하는지 사람이 확인해야 하는 이유: AI는 “세 번 재시도”나 “백그라운드 복귀” 같은 미정의 정책도 제안할 수 있다.
- 보상 중복 검증에서 거래 ID 집합뿐 아니라 실제 **보상 기록 횟수**를 검사하는 이유: 집합만 확인하면 같은 ID로 두 번 적립된 결함을 놓친다.
- 자동화의 범위: 가상 상태 시뮬레이터의 회귀 검증이다. 앱·SDK·서버 연동과 실제 사용자 경험은 별도 환경에서 확인해야 한다.
