# 가상 AMR 주행·지도·QA 환경 구축 가이드

상태: **설계 가이드 작성** (2026-11-24). 이 문서의 새 환경은 아직 구현·실행하지 않았습니다.

## 목표와 범위

실내의 가상 로봇이 지도를 보며 목표점으로 이동하고, 장애물과 오류 상황에서 어떻게 반응하는지 반복 시험할 수 있는 환경을 만듭니다. 참고 영상은 지도·경로·로봇 상태를 보여 주지만 원본 프로그램의 ROS 2 사용 여부는 확인되지 않았습니다. 따라서 영상의 동작을 목표로 삼되 원본 소프트웨어나 기술 스택을 그대로 재현한다고 가정하지 않습니다.

첫 목표는 **1대의 차동구동 로봇, 1개 층, 1개 지도, 목표점 이동과 장애물 정지·재계획**입니다. 여러 로봇, 도킹, 배터리, 관제 서버는 이 흐름이 안정된 뒤 확장합니다. 기존 [AMR QA 랩](../../../projects/amr-qa-lab/README.md)은 미션 상태·테스트 설계의 참고 자료이며, 물리 주행이나 SLAM이 구현된 환경은 아닙니다.

## 시작 방식

| 방식 | 적합한 목표 | 핵심 구성 |
| --- | --- | --- |
| 가벼운 2D 시뮬레이터 | 영상처럼 지도 위 이동·경로·상태·QA를 먼저 확인 | 2D 지도 화면, 독립된 주행 계산, 충돌·센서·로그 |
| ROS 2 연동 환경 | ROS 2 메시지·TF·SLAM Toolbox·Nav2를 실제로 학습 | 시뮬레이터 또는 Gazebo, `/scan`·`/odom`·`/tf`, RViz, SLAM·Nav2 |

**권장 순서:** 현재 Mac은 8GB 메모리이며 UTM의 4GB Ubuntu VM에서 Jazzy와 RViz는 실행됐지만 Gazebo 예제의 오도메트리·TF가 확인되지 않았고 최소 월드 실행 중 입력 지연도 있었습니다. 우선 2D 방식으로 주행·QA의 최소 기능을 만들고, ROS 2 통합은 별도 단계로 진행합니다. 이 순서는 현재 장비에서 관찰한 결과에 따른 제안이며, 2D 방식이 모든 장비에서 더 빠르다는 일반적 성능 주장으로 해석하지 않습니다. [UTM 실행 기록](../evidence/2026-11-24-utm-ros-install.md)

## 공통 설계 원칙

1. **계산과 화면 분리:** 로봇 위치·센서·경로·상태는 시뮬레이션 코어가 계산합니다. 화면은 같은 상태를 읽어 표시합니다. 화면에서 로봇 그림만 움직이는 방식은 주행 검증이 아닙니다.
2. **기준 좌표 분리:** 시뮬레이터의 참값(ground truth), 바퀴 오도메트리, 추정 위치를 별도 값으로 보관합니다. 화면에도 구분해서 표시하면 위치 오차를 시험할 수 있습니다.
3. **재현 가능한 시간:** 고정 시간 간격으로 상태를 갱신하고 난수 시드를 저장합니다. 시뮬레이션 시간, 실시간 대비 속도, 일시 정지·재시작을 정의합니다.
4. **지도 상태 구분:** 처음부터 주어진 정적 지도와 센서로 새로 작성한 지도는 다른 산출물입니다. 정적 지도를 표시했다는 이유로 SLAM 성공이라고 기록하지 않습니다.
5. **시험 가능한 이벤트:** 명령, 상태 전이, 충돌, 장애물 감지, 경로 변경, 도착·실패 사유를 시각과 함께 남깁니다. 가상 사양과 실제 제품 데이터를 섞지 않습니다.

## 단계별 구축 순서와 완료 기준

| 단계 | 구현할 최소 기능 | 완료를 보여 주는 증거 |
| --- | --- | --- |
| 1. 지도·좌표 | 가상의 복도·방·벽으로 만든 2D 점유 격자, m↔픽셀 변환, 로봇 크기와 시작 위치 | 지도 파일을 다시 열어도 크기·해상도·좌표가 같고, 벽과 자유 공간이 구분됨 |
| 2. 로봇 주행 | 차동구동 속도 명령, 시간 간격별 위치 갱신, 최대 속도·회전 속도, 벽 충돌 방지 | 직진·제자리 회전·정지 명령이 예상 방향으로 작동하고 벽을 통과하지 않음 |
| 3. 가상 센서·위치 | 라이다 광선과 거리값, 바퀴 오도메트리, 선택 가능한 노이즈, 참값과 추정값 | 같은 시드에서 같은 로그를 얻고, 노이즈를 켜면 위치 오차가 측정됨 |
| 4. 관측 지도·SLAM | 2D에서는 참값 위치와 센서 관측으로 점유 격자를 갱신합니다. 실제 SLAM 검증은 참값에 기대지 않는 오도메트리·스캔 입력으로 별도 수행합니다. ROS 2 경로에서는 SLAM Toolbox를 연동할 수 있습니다. | 시작 지도와 탐색 후 지도가 다르고, 저장·재로드 뒤 장애물 위치가 유지됨. SLAM 성공 표시는 추정 위치와 참값의 오차도 확인한 뒤에만 사용 |
| 5. 목표 주행 | 목표점 지정, 전역 경로, 경로 추종, 장애물 앞 정지·재계획, 도착 판정 | 경로·실제 궤적·도착 오차가 함께 보이고, 막힌 경로에서 벽을 통과하지 않음 |
| 6. QA 시나리오 | 장애물 추가·제거, 센서 중단·오차, 배터리 임계값, 비상정지, 도킹은 선택 확장 | 시나리오마다 기대 상태·실제 상태·이벤트 로그·재현 조건을 남김 |

**첫 데모 완료선:** 정적 지도의 시작점에서 목표점을 지정하면 로봇이 충돌 없이 이동하고, 경로에 장애물을 놓으면 정지한 뒤 가능한 경우 새 경로로 도착합니다. 같은 시드를 다시 실행했을 때 동일한 결과와 로그가 나와야 합니다. 지도 *작성*을 보여 주려면 4단계의 센서 기반 갱신 증거를 별도로 준비합니다.

## ROS 2를 붙일 때의 점검 순서

2D 코어가 동작한 뒤 ROS 2가 필요한 경우에만 인터페이스를 정합니다. 로봇의 속도 명령(`/cmd_vel`), 오도메트리(`/odom`), 레이저 스캔(`/scan`), 프레임 변환(`/tf`), 지도(`/map`), 시뮬레이션 시계(`/clock`)가 서로 일관되게 발행되는지 확인합니다. `map → odom → base_link` 변환과 시간 설정이 맞지 않으면 RViz나 Nav2에서 이름만 보이는 토픽으로는 주행 성공을 판단할 수 없습니다. 이후 지도 작성은 SLAM Toolbox, 저장 지도에서의 위치 추정·목표 주행은 Nav2로 검증합니다. Gazebo를 선택한다면 Gazebo와 ROS 2 사이의 필요한 메시지를 `ros_gz_bridge`로 연결합니다.

## 기록할 최소 산출물

- **설계:** 공개 가능한 가상 지도 사양, 로봇 크기·속도·센서 범위, 좌표계와 상태 전이표.
- **실행:** 실행 명령, 환경 버전, 난수 시드, 입력 미션·장애물 설정, 예상·실제 결과.
- **증거:** 지도 전후 파일, 로봇 궤적·경로 화면, 오도메트리와 참값 비교, 이벤트 로그, 실패 재현 절차.
- **상태:** 계획·작성·실행 확인을 구분합니다. 영상과 비슷한 화면이 나왔다는 사실만으로 SLAM·자율주행·안전성을 검증했다고 표시하지 않습니다.
