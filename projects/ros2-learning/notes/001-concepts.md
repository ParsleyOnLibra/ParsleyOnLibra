# 001 · ROS 2 기본 개념과 AMR QA

날짜: 2026-10-29 · 구분: 첫 개념 설명 정리 · 실습: 미실행

## 학습 목표

노드·토픽·서비스·액션의 역할을 구분하고, AMR 문제를 데이터 흐름으로 살펴볼 관점을 익힙니다. 아래 AMR 구성은 학습용 가상 설계입니다.

ROS 2는 로봇 소프트웨어 개발을 위한 도구와 라이브러리를 제공하는 플랫폼입니다. 여러 기능을 담당하는 구성 요소를 연결해 센서 처리, 경로 계획, 구동 제어 등을 함께 동작시키는 데 사용합니다.

| 개념 | 의미 | 가상 AMR 예시 |
| --- | --- | --- |
| Node | 특정 역할을 수행하는 소프트웨어 구성 요소 | 배터리 상태 처리, 도킹 제어 |
| Topic | Publisher가 메시지를 발행하고 Subscriber가 구독하는 통신 통로 | 배터리 잔량, 센서 데이터 |
| Service | 요청과 응답을 주고받는 방식 | 상태 조회, 초기화 요청 |
| Action | 시간이 걸리는 작업의 목표·피드백·결과와 취소 요청을 다루는 방식 | 목적지 이동, 도킹 |

토픽은 지속적인 데이터 전달에 적합합니다. 액션은 이동처럼 시간이 걸리고 중간 진행 상황을 확인해야 하는 작업에 적합합니다. 액션 취소 요청이 반드시 수락되거나 물리적 정지를 보장하는 것은 아닙니다.

## 배터리 예시

`배터리 노드 → /battery_level 토픽 → 관제 노드`

배터리 노드는 Publisher, 관제 노드는 Subscriber 역할입니다. `/battery_level`은 이 노트에서 정한 예시 이름입니다. 실제 메시지 형식과 발행 주기는 실습 설계에서 결정합니다.

## QA 관점의 관찰 질문

로봇이 이동 중 멈췄다면 다음을 확인할 수 있습니다.

- 센서 데이터가 계속 도착하는가?
- 장애물 감지값이 실제 상황과 맞는가?
- 이동 명령이 전달되는가?
- 이동 작업의 상태와 실패 사유가 무엇인가?
- 같은 조건에서 재현되는가?

아직 실제 로봇이나 ROS 2 환경에서 확인한 결과는 없습니다.

## 이해도 확인 — 아직 답변 전

1. 배터리 잔량을 계속 전달할 때 토픽이 적합한 이유는 무엇인가?
2. 목적지 이동을 서비스 대신 액션으로 설계하면 어떤 정보를 추가로 다룰 수 있는가?
3. 데이터가 오지 않을 때 발행 노드와 구독 노드에서 각각 무엇을 확인해야 하는가?
