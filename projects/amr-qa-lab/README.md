# AMR 미션·도킹 QA 테스트 랩

**[실행 결과 웹 보기](https://parsleyonlibra.github.io/ParsleyOnLibra/projects/amr-qa-lab/)** · [요구사항](docs/REQUIREMENTS.md) · [테스트 설계](docs/TEST_DESIGN.md) · [테스트케이스 20개](docs/TEST_CASES.md) · [결함 기록](docs/DEFECTS.md)

로봇 QA에서 중요한 **요구사항 분석 → 테스트케이스 도출 → 실행 → 결함 재현 → 회귀 확인**을 한 프로젝트에 담았습니다. 테스트 대상은 직접 만든 결정적 AMR 상태 시뮬레이터입니다. 실제 유진로봇 제품, 고객 환경 또는 안전 인증 결과가 아닙니다. 배터리 20% 등 모든 수치는 이 연습용 사양에서 정했습니다.

## 무엇을 검증했나

- 미션 시작 조건: 로봇 상태, 지도, 경로, 배터리 경계
- 장애물 감지·해제와 이동 재개 조건
- 비상정지 중 명령 거부와 해제 후 자동 재개 방지
- 도킹 성공·타임아웃·장애 초기화
- 잘못된 배터리 입력과 중복·잘못된 순서의 명령

테스트 설계에는 결정표, 경계값 분석, 동등분할, 상태 전이를 적용했습니다. 케이스마다 요구사항 ID, 우선순위, 사전 조건, 절차, 예상 코드를 연결했습니다. 일부러 만든 결함 3종을 주입해 어떤 케이스가 검출하는지도 확인했습니다. 이들은 실제 로봇 결함이 아닙니다.

## 재현

Python 3.10 이상만 필요합니다. 외부 패키지나 실제 로봇 장비가 필요하지 않습니다. 저장소 루트에서 실행합니다.

```powershell
python projects/amr-qa-lab/scripts/run_cases.py
python projects/amr-qa-lab/scripts/check_mutations.py
python projects/amr-qa-lab/scripts/build_case_matrix.py
```

현재 결과는 [실행 보고서](results/latest.json)에서 **20/20 케이스 통과**, [오류 주입 보고서](results/mutations.json)에서 **3/3 검출**입니다. 실행 보고서는 동일한 입력으로 다시 생성할 수 있고, 명령별 기대·실제 반환값과 이벤트 로그를 포함합니다.

## 실제로 발견한 테스트 설계 문제

첫 실행에서는 “배터리 20% 승인” 케이스가 기본 배터리 50%로 돌고 있어 경계값 오류를 놓쳤습니다. 오류 주입으로 이를 발견하고 사전 조건을 수정했습니다. [QA-LAB-001](docs/DEFECTS.md)에 발견·재현·수정·회귀 결과를 남겼습니다. 이는 상용 로봇 버그가 아니라 **테스트케이스의 결함**입니다.

## 남은 범위

시뮬레이터는 센서 지연, 물리적 위치 오차, 실제 지도 생성, 충전 전류, 관제 웹 브라우저 연결을 모델링하지 않습니다. 자동 테스트의 통과가 현장 로봇의 안전성이나 성능을 증명하지는 않습니다. 나중에 실제 또는 공개 시뮬레이션 시스템을 테스트한다면 요구사항과 실행 환경을 별도로 정의해야 합니다.
