# 가상 AMR 관제 요구사항 v1

이 문서는 **공개 QA 연습용으로 만든 가상 사양**이다. 실제 Gocart, 유진로봇 제품, 고객 환경의 명세나 결과가 아니다. 평가 대상은 `src/amr_sim.py`의 결정적 상태 시뮬레이터다.

## 상태와 관측 방법

`IDLE`, `MOVING`, `BLOCKED`, `DOCKING`, `CHARGING`, `FAULT`, `ESTOP`를 사용한다. 모든 명령은 `accepted`, `code`, `state`를 반환하고, 승인과 거부를 모두 순번·이전 상태·이후 상태와 함께 이벤트 로그에 기록한다. 같은 입력과 명령 순서는 항상 같은 결과를 낸다.

| ID | 요구사항 | 중요도 | 승인 조건 및 거부 결과 |
| --- | --- | --- | --- |
| R-01 | 미션은 `IDLE`이며 지도와 유효 경로가 있을 때만 시작한다. | 높음 | 성공 `MOVING`; 지도 없음 `MAP_MISSING`, 경로 없음 `ROUTE_INVALID`, 그 외 상태 `INVALID_STATE` |
| R-02 | 새 미션은 배터리 20% 이상에서만 시작한다. | 높음 | 19%는 `BATTERY_LOW`, 20%와 21%는 승인. 다른 시작 조건이 충족됐을 때 적용 |
| R-03 | 이동 중 경로 장애물 감지 시 `BLOCKED`로 정지한다. 해제된 뒤에만 `MOVING`으로 돌아간다. | 높음 | 허용되지 않은 상태의 감지·해제는 `INVALID_STATE`; 반복 감지는 재개를 만들지 않음 |
| R-04 | 비상정지는 다른 명령보다 우선한다. `ESTOP`에서는 미션·도킹·장애물 해제 등을 거부하며, 해제 후 `IDLE`로 돌아간다. | 매우 높음 | 비상정지 중 거부 `ESTOP_ACTIVE`; 해제해도 이전 미션이 자동으로 재개되지 않음 |
| R-05 | 도킹은 `IDLE` 또는 `MOVING`에서 도크가 있을 때 시작한다. 성공 시 `CHARGING`, 타임아웃 시 `FAULT`가 된다. | 높음 | 도크 없음 `DOCK_UNAVAILABLE`; `FAULT`는 명시적 초기화 후 `IDLE`; 타임아웃 뒤 성공 신호는 거부 |
| R-06 | 배터리 설정은 정수 0~100만 허용한다. | 보통 | 범위 밖 또는 비정수는 `INVALID_BATTERY`이고 이전 값은 유지 |

## 전제와 범위 밖

- 지도·경로·도크 유무와 최초 배터리 값은 각 테스트의 사전 조건으로 설정한다. 20%는 실제 로봇의 배터리 정책이 아닌 가상 경계다.
- 장애물의 물리적 거리, 지도 생성 알고리즘, 충전 전류, 실제 센서 지연은 시뮬레이터가 모델링하지 않는다.
- 도킹 요청은 진행 중 미션을 대체할 수 있다. `ESTOP`은 어느 상태에서도 누를 수 있다.
- 사양 변경 시 테스트 예상 결과를 먼저 검토하고, 결과를 바꾸는 이유를 기록한다.
